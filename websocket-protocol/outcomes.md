### outcomes

#### `outcomes.scoreboard`
- **Params**: `null`
- **Returns**: the persistent, OUTCOME-DENOMINATED scoreboard folded from the durable outcome ledger (`models_dir/outcome_ledger.jsonl`):
  `{ rows: ScoreboardRow[], total_successes, total_failures, total_inconclusive, total_usd: number | null, total_usd_is_estimate: boolean, overall_usd_per_success: number | null, model_count, receipts }`, where each `ScoreboardRow` is `{ model_id, success_count, fail_count, inconclusive_count, total_input_tokens, total_output_tokens, avg_quality: number | null, avg_latency_ms, success_rate: number | null, tokens_per_success: number | null, usd_per_success: number | null, usd_is_estimate: boolean }`.
- `usd_per_success` (priced spend ÷ successes) is the headline per-model metric — the dollars-per-correct-outcome the "cry once" thesis is legible in; `overall_usd_per_success` is the deployment-wide figure. Values are `null` rather than fabricated: `usd_per_success`/`total_usd` are `null` for unpriced models, `success_rate`/`tokens_per_success` are `null` until something resolves, and `inconclusive_count` (completed-but-unscored receipts) is surfaced so the denominator's coverage is legible. `usd_is_estimate` and `total_usd_is_estimate` are true for prompt-tiered models whose already-aggregated ledger totals can only be priced at the catalog base tier; consumers must label those values as estimates. Rows are sorted cheapest-correct-outcome first.
- Distinct from `models.stats`: that is the **live in-memory** profiles; this reads the **cross-session ledger** (survives restart, de-biased by the pending-sweep) and joins per-model catalog prices. The FFI `outcome_scoreboard()` (NAPI/PyO3) returns this same JSON as a string.

#### `outcomes.resolve_pending`
- **Params**: `{ actionResults: [[traceId, success, confidence, output], ...] }` — flat tuples produced by a `car-reason` session's `ActionOutcome` vector. `traceId` is a string (`""` is treated as "no trace, skip"); `success` is a boolean; `confidence` is a float `[0.0, 1.0]`; `output` is the generated text.
- **Returns**: `{ recorded: number }` — the reports that matched a pending trace and were recorded. A tuple with an empty `traceId` is skipped and not counted.
- **Dropped reports are an error, not a count.** When any report matches no pending trace (already resolved, not started by this daemon, or swept), the ones that did match are still recorded, and the call fails with `-32019` and `error.data = { reason: "trace_not_pending", recorded, dropped: [traceId, ...] }`. `recorded` is what landed; a retry cannot double-count it, because a resolved trace is no longer pending. Before car-releases#110 a dropped report was silently counted in `recorded`.
- **How long a trace stays pending.** A call that ended stays gradeable for 900 seconds after it **ended** (completed, or stopped without a completion), however long it ran. A call still in flight is never swept for that reason; it is dropped only two hours after it started, the bound for a call that crashed without ending. Before car-releases#110 the window was 300 seconds from the call's **start**, so a call longer than that could not be graded at all.
- Symmetric to the in-process `ReasoningInferenceHandle::record_inferred_outcomes` impl. The daemon runs `OutcomeTracker::infer_outcomes_from_action_sequence` to convert the tuples into resolved outcomes, then writes them back under the tracker's write lock. Lets the routing-learning loop survive daemon-routed reasoning sessions instead of silently no-op'ing.
- Closes the follow-up flagged in Parslee-ai/car#189. Older daemons without this method respond with JSON-RPC `-32601`; the CLI's `DaemonInferenceHandle::record_inferred_outcomes` catches that specific code and falls back to its pre-existing soft no-op so a CLI / daemon version skew during a rolling upgrade doesn't crash reasoning sessions. It ignores a `-32019` the same way: the reasoning result does not depend on the learning loop.

#### `outcomes.record_external_grade`
- **Params**: `{ model_id: string, task: "generate" | "embed" | "classify" | "code" | "reasoning", quality: number, n?: number, source: string, allow_unknown_model?: boolean }`. `quality` is the mean grade over `n` cases, in `[0, 1]`; `n` defaults to `1` and may be at most `100`. `source` names who graded it (`neo`, `nightly-eval`), 1 to 64 characters of `[A-Za-z0-9._:-]`. Unknown fields are refused.
- **Returns**: `{ model_id, known_model, task, source, source_key, n, source_quality, source_observations, source_evidence }`. `model_id` is the catalog id the grade was recorded under; `source_key` is the key the source is stored under (see **Who is reporting**); `source_quality`, `source_observations` and `source_evidence` describe this source's state for the model and task after the report.
- Records a graded result for a model this daemon did **not** serve, for example an outside head-to-head (car-releases#110). Use `outcomes.resolve_pending` instead for a call that went through `infer_tracked`.
- **Model id.** It resolves the way generation resolves a model, exact id first and then name, to the catalog row the router scores. An id CAR does not know is refused with `unknown_model`; pass `allow_unknown_model: true` to record it under the id as given.
- **Who is reporting.** The daemon, not the caller, decides who a report comes from. A session bound to a supervised agent reports as `agent:<id>`, and its source is stored as `agent:<id>/<source>`; every other session is an operator, and its source is stored under the name given. A source name cannot contain `/`, so an agent can neither overwrite an operator's `neo` nor another agent's sources.
- **How the grade reaches routing.** Each source's grades are kept per model and task, apart from the outcomes of served calls: they change no call counts, no success or failure counts, and not the served quality EMA. A source's quality is a running mean over its reports whose window is capped at 8 cases, so a newer verdict keeps moving it, and reporting again under the same source with `n` of 8 or more replaces its quality outright. `models.route` pools the grades into `reliability` at benchmark weight, one unit per case, under three caps: 8 units per source, 8 units for all of one reporter's sources together, and 16 units for every reporter together. One reporter, whatever source names it uses, therefore moves a model's `reliability` at most two thirds of the way from its catalog prior to the quality it reports, and all external grades together at most four fifths; graded calls the daemon served are not capped. Each route candidate lists the grades under `external_grades` (see [`models.route`](inference.md#modelsroute)).
- **Expiry and source slots.** A source not updated for 90 days stops counting toward `reliability`; reporting under it again starts it afresh. Each reporter may keep 8 current sources per model and task. A new source past that takes the slot of the reporter's stalest source if that one has gone stale, and is refused with `source_limit_reached` otherwise. There is no call that deletes a source; correct a mistaken grade by reporting under the same source again.
- **Limits.** Each supervised agent may report 30 times a minute, and operator sessions share one budget of 30 a minute; past that the call is refused with `rate_limited` and `error.data.retry_after_secs`. The profile is written to disk before the call returns; if that write fails, the call is refused with `persist_failed` and the grade is taken back, so it does not count in memory either and a retry counts it once (car#3515).
- **Errors.** Every refusal is `-32019` with `error.data.reason`: `unknown_model`, `invalid_quality`, `invalid_n`, `invalid_source`, `invalid_model`, `invalid_reporter`, `source_limit_reached`, `rate_limited` or `persist_failed`. A malformed or missing field is `invalid params`.
